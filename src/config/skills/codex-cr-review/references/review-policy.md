# Review Policy（评审规则）

## 一、严重性 rubric

### P0（阻断）

使用 `P0` 标识必须阻断合并的问题：

| 场景 | 说明 | 示例 |
|------|------|------|
| 生产故障 | 服务宕机、严重可用性风险 | 数据库连接池耗尽 |
| 安全漏洞 | 权限绕过、注入攻击 | SQL 注入、XSS |
| 数据丢失 | 数据损坏、不可逆迁移 | 未备份的数据迁移 |
| 正确性 bug | 主路径上的明显逻辑错误 | 条件判断错误 |
| 部署风险 | 破坏部署、启动或关键流程 | 缺少必需的环境变量 |

**必需行动**：
- 在确切的代码行留下 inline 评论
- 明确指出"不要合并"
- 不批准 MR

---

### P1（建议修复）

使用 `P1` 标识重要但非阻断的问题：

| 场景 | 说明 | 示例 |
|------|------|------|
| 用户 bug | 非关键路径的用户问题 | 边缘场景显示错误 |
| 回归风险 | 强回归风险 | 修改了共享函数 |
| 缺少防护 | 缺少错误处理 | 未 catch 的 Promise |
| 测试缺失 | 风险代码缺少测试 | 新 API 无单元测试 |

**行动**：
- 在确切的代码行留下 inline 评论
- 建议修复后再合并

---

### P2（可选改进）

使用 `P2` 标识非阻断改进：

| 场景 | 说明 | 示例 |
|------|------|------|
| 可维护性 | 代码结构问题 | 过长的函数 |
| 清晰度 | 命名不清晰 | 缩写命名 |
| 边缘情况 | 边缘情况处理 | 缺少日志 |
| 小改进 | 小优化 | 可抽取公共逻辑 |

**行动**：
- 可选择性留下 inline 评论
- 非阻断，可后续处理

---

## 二、评审检查清单

### 正确性
- [ ] 逻辑错误（条件判断、循环、递归）
- [ ] 边界条件（空值、零值、最大值）
- [ ] 并发问题（竞态条件、死锁）
- [ ] 状态一致性（事务、回滚）

### 安全性
- [ ] 注入风险（SQL、XSS、命令注入）
- [ ] 权限校验（未授权访问、越权）
- [ ] 敏感数据（密钥、密码、token）
- [ ] 输入验证（类型、长度、格式）

### 回归风险
- [ ] 向后兼容性（API、数据结构）
- [ ] 迁移风险（数据库、配置）
- [ ] 配置变更（环境变量、开关）
- [ ] 依赖升级（破坏性变更）

### 测试覆盖
- [ ] 新代码有对应测试
- [ ] 边界情况有测试
- [ ] 错误路径有测试
- [ ] 现有测试通过

### 可维护性
- [ ] 命名清晰
- [ ] 注释充分
- [ ] 代码复杂度合理
- [ ] 无明显重复代码

## 三、输出模板

### Inline 评论模板

**P0**：
```
[P0] 这里会导致 <关键行为> 出错，因为 <原因>。在 <必须修复项> 完成前不要合并。
```

**P1**：
```
[P1] 这里在 <条件> 下会失败，因为 <原因>。请改为 <期望修复方式>。
```

**P2**：
```
[P2] 这里容易被误解或误用，因为 <原因>。建议改成 <期望改进方式>。
```

## 四、特殊场景处理

### 1. 无问题

```markdown
**评审结果**：`non-blocking`

**问题统计**：P0 x0, P1 x0, P2 x0

**合并建议**：本轮评审确认当前无阻断合并的问题。

**正面评价**：
- 代码质量良好，无明显问题
- 测试覆盖充分
```

### 2. 大 MR（文件过多）

优先关注高风险区域：
1. 核心业务逻辑
2. 数据处理/存储
3. 权限/认证相关
4. 外部 API 调用
5. 配置变更

### 3. 增量复评

同一 MR 多次推送时：
- 读取已有评论
- 比对最新 diff
- 更新旧 finding 状态（resolved/open/superseded）
- 仅新增 net-new finding

---

## 五、禁止事项

- 不修改人工评论
- 不创建重复评论
- 不在总结中引入新的 inline 问题
- 不将风格问题升级为 P1/P0
