# Codex CR Review

简化版 GitLab MR 代码评审技能。接收用户提供的 MR 链接，读取 MR 数据后输出结构化的评审报告。

## 使用方式

```text
帮我看看这个 MR https://git.singularity-ai.com/editor/image/-/merge_requests/123
```

## 核心原则

1. **GitLab 是唯一状态源** — 所有 MR 信息以 GitLab API 返回为准
2. **逐行评审** — 仔细阅读 diff，不跳过任何改动
3. **分类输出** — 所有问题按 P0/P1/P2 分级
4. **只读分析** — 不写回 GitLab，仅输出评审报告

## 评审流程

1. **解析 MR 链接** — 提取项目路径和 MR IID
2. **读取 MR 数据** — 调用 GitLab API 获取元数据、diff、评论
3. **执行评审** — 按评审规则分析代码
4. **输出报告** — 结构化 markdown 格式

## 严重性定义

### P0（阻断）

必须修复才能合并：
- 生产故障或严重可用性风险
- 安全漏洞或权限绕过
- 数据丢失、损坏或不可逆迁移风险
- 主路径上的明显正确性 bug
- 会破坏部署、启动或关键用户流程的改动

**行动**：明确指出"不要合并"

### P1（建议修复）

重要但非阻断：
- 可能影响用户的 bug（非关键路径）
- 强回归风险
- 缺少防护、重试、验证或错误处理
- 风险代码的测试缺失

**行动**：建议修复后再合并

### P2（可选改进）

非阻断改进：
- 可维护性问题
- 清晰度问题
- 边缘情况
- 小的测试或可观测性改进

**行动**：非阻断，可后续处理

## 评审维度

| 维度 | 关注点 |
|------|--------|
| 正确性 | 逻辑错误、边界条件、空值处理、并发问题 |
| 安全性 | 注入风险、权限校验、敏感数据、密钥管理 |
| 回归风险 | 兼容性、迁移风险、配置变更、回滚难度 |
| 测试覆盖 | 新代码是否有对应测试、测试是否充分 |
| 可维护性 | 命名、注释、复杂度、重复代码 |
