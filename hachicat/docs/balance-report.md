# 战斗难度、怪物多样性与奖励经济平衡报告

日期：2026-10-23
项目：`hachicat`（哈气猫）
基线提交：`bf9ffee`（`feat(render): 主角移动与待机加入时间驱动的程序化动画`）

> 数据口径：本报告里的“模拟”全部来自确定性无头机器人 `tools/balance-sim.mjs`，
> 不是真人试玩。机器人会读预警、侧闪弹幕、完美贴边，因此它的通关率是玩家表现的**上限**；
> 真人手感仍需手机试玩校准。自动化测试与模拟数据分开列在“验证”一节。

## 1. 方法与样本

- 基线：用 `git worktree` 检出 `bf9ffee`，把同一份模拟脚本放进基线目录运行，避免“改后脚本测改前代码”的口径差。
- 样本：3 个角色（小八 / 吉伊 / 乌萨奇）× 3 个固定种子（`20260101`、`20268020`、`20275939`）× 6 个场景 = **54 局/版本**。
- 场景：
  - `none`：完全不买。
  - `normal`：武器优先、道具其次、残血治疗。
  - `weapon`：极端的武器投资，几乎不买道具。
  - `heal`：频繁治疗，保留治疗费。
  - `reroll`：每次商店只要有钱就刷新 2 次。
  - `slowstart`：前 3 波不买，模拟糟糕开局。
- 每局记录：每波击杀、受伤、伤害输出、经验、收入、商店支出、等级、同屏敌人峰值、时长；
  改后版本额外记录突进预警、自爆引信、召唤、维修、首领弹幕次数，以及按敌人来源的受伤统计。
- 命令：

```bash
node tools/balance-sim.mjs --scenario all --runs 3 --json /tmp/after.json
node tools/balance-sim.mjs --scenario normal --build ranged --runs 3
node tools/balance-sim.mjs --scenario normal --build melee --runs 3
```

## 2. 总览：难度与经济的改前 / 改后

| 场景 | 胜率（前→后） | 平均受伤（前→后） | 平均剩余金币（前→后） | 平均等级（前→后） |
| --- | --- | --- | --- | --- |
| none（不买） | 0% → 0% | 106.9 → 107.0 | 342.0 → 306.9 | 5.2 → 4.7 |
| normal | 100% → 100% | 66.6 → **120.6** | 209.8 → **69.3** | 12.9 → 12.8 |
| weapon | 100% → **77.8%** | 62.4 → **117.8** | 235.6 → 100.2 | 13.0 → 11.6 |
| heal | 100% → 100% | 73.0 → **148.7** | 220.4 → 163.0 | 12.8 → 12.8 |
| reroll | 77.8% → 77.8% | 73.4 → **149.1** | 76.6 → **47.3** | 11.7 → 11.2 |
| slowstart | 100% → 100% | 140.7 → **183.4** | 228.6 → 137.3 | 12.2 → 12.3 |

- “平均剩余金币”是打完第 12 波后的局内金币，不含委托结算。
- 机器人仍然能通关 `normal` / `heal` / `slowstart`，但平均受伤接近翻倍；`weapon` 与 `reroll`
  出现 2/9 阵亡。**这是“强机器人上限”，不是真人通关率。**
- 阵亡波次：改后 `none` 为 5–10 波（基线 6–9 波）；`weapon` 为 7、8 波；`reroll` 为 4、10 波。

### 为什么 `normal` 还是 100%？

机器人会在 0.1 秒内对突进 / 引信 / 首领冲刺做出反向位移，并把弹幕当成几何题来侧闪。
本次新增的 5 种普通怪里，疾走快递、铁皮箱、漏电电池、孵化箱、维修灯都以“逼近 / 自爆 /
召唤 / 治疗”为主，正好是完美走位最容易规避的类型；真正打中机器人的仍然是远程喷水壶和首领弹幕。
因此这组数据只能证明“伤害与资源压力显著上升”，不能证明“真人也会 100% 通关”。

## 4. 阶段设计（12 波）

| 阶段 | 波次 | 设计 |
| --- | --- | --- |
| 基础 | 1–3 | 只有扫地机、无人机；第 3 波加入喷水壶，教玩家躲弹幕 |
| 变化 | 4–6 | 第 4 波疾走快递 + 垃圾桶怪，第 5 波铁皮箱，第 6 波漏电电池；开始出现“先处理谁”的选择 |
| 精英与协同 | 7–9 | 第 7 波孵化箱、第 8 波维修灯；第 7 波起按 `eliteEvery` 出精英；维修灯 + 铁皮箱 + 孵化箱形成拖时间组合 |
| 高压 | 10–11 | 同屏上限 36/40，刷新间隔 0.38/0.32；多类型混编，精英更密 |
| 首领 | 12 | 铁肺 9000 HP，三阶段：环形弹幕 → 冲锋/召唤 → 螺旋弹幕 |

新增怪物按波次逐步解锁，不会开局把所有机制堆给玩家；每波池子权重都在
`src/content/waves.js`，没有把数值写进 AI。

## 6. 经济参数改前 / 改后

| 项目 | 基线 | 改后 | 目的 |
| --- | --- | --- | --- |
| 波次通关奖励 | 14/16/18/20/22/24/26/28/30/32/40 | 14/16/18/20/22/24/26/28/28/30/34 | 前期不变；后期略降基础奖励，靠击杀与精英补 |
| 通关公式 | `reward + 6 + 2n` | 不变 | 保持可读 |
| 武器基础价 | 18 / 30 / 46 | 20 / 34 / 52 | 前期武器略贵，必须取舍 |
| 武器等级溢价 | `1 + 0.3(L-1)` | `[1, 1.5, 2.25, 3.4, 4.8]` | 高等级升级成为后期金币出口 |
| 副本概率 / 价格 | 30% / 直购价 45% | 30% / 直购价 42% | 合成路线保留折扣但不再压倒直购 |
| 道具价格 | 18–38 | 21–45 | 前期不能一次买空商店 |
| 治疗 | 38% 上限，`14 + 7%` 上限价 | 34% 上限，`18 + 9%` 上限价 | 高血量治疗更贵，不能无脑续命 |
| 刷新 | 首次 6，之后 +3 | 8 / 11 / 17 / 26 / 38… | 刷新越多次越贵，不能免费刷理想装备 |
| 经验曲线 | `6 + 6L + L^1.4` | `8 + 7L + L^1.45` | 抵消新增怪物带来的经验增量 |
| 委托 | 底薪 30，胜利 +60 | 底薪 30，胜利 +80 | 胜利明显优于失败，失败仍有底薪 |
| 首领 | 2600 HP / 22 伤害 / 护甲 4 | 9000 HP / 26 伤害 / 护甲 5 | 把 4 秒首领战拉成真正的阶段战 |
| 普通怪缩放 | 生命 +17%/波、伤害 +8%/波、护甲每 5 波 | +22% / +10% / 每 4 波 | 不靠堆同屏数量，也提高单体质量 |

### 收入与支出是否自洽

- 第 1 波收入 40.7，商店 4 件商品总价通常 80–190：**买得起 1–2 件，不可能买空**。
- 第 5 波收入 84.6、支出 89.8：开始出现“买武器还是买道具/治疗”的取舍。
- 第 11 波收入 254.8、支出 236.9：满级武器价格 96（稀有 1）/163（稀有 2）/250（稀有 3），
  加上副本与道具，金币有明确出口。
- `none` 仍然 0% 通关：不构建就死在 5–10 波，说明经济不是“不买也能过”。
- 失败委托总收益 30，胜利最低 30 + 材料 + 80，**失败不会优于胜利**。

## 7. 不同 build 的模拟结果（normal 策略，3 角色 × 3 种子）

| Build | 胜率 | 平均受伤 | 平均等级 | 剩余金币 | 首领弹幕/局 |
| --- | --- | --- | --- | --- | --- |
| 完整购物（不限武器） | 100% | 120.6 | 12.8 | 69.3 | 3.9 |
| 远程限定（毛球弹 / 激光笔） | 100% | 118.1 | 13.1 | 341.8 | 3.4 |
| 近战限定（磨爪 / 哈气 / 尾巴 / 捕鼠夹） | 100% | 275.8 | 11.9 | 222.7 | 5.7 |
| 只买武器 | 77.8% | 117.8 | 11.6 | 100.2 | 2.3 |
| 频繁治疗 | 100% | 148.7 | 12.8 | 163.0 | 2.9 |
| 频繁刷新 | 77.8% | 149.1 | 11.2 | 47.3 | 3.6 |

- 远程与近战都能通关，但代价不同：近战平均多挨 2.3 倍伤害、等级更低；
  远程更安全，但“只买远程武器”的机器人会主动放弃其它商品，所以剩钱多，这不是经济漏洞，
  而是限定 build 的选择成本。
- 只买武器 / 频繁刷新会把钱花在成长或随机性上，容错更低，出现阵亡。

## 9. 未验证 / 不能声称完成的部分

- **没有真人试玩数据**。所有胜率、受伤、金币都是机器人模拟；手机摇杆手感、预警可读性、
  近战怪的实际压迫感必须真人试玩。
- 没有低端真机数据；60 fps 是桌面 Chrome + DPR 2 的结果。
- 微信小游戏只做了假 wx + Canvas 冒烟，没有开发者工具/真机验证；新怪物在微信端理论上复用同一
  `render/`，但没有真机截图。
- 没有做音效、UI 布局、角色数值/立绘/移动动画的改动；这些不在本次边界内。
